# 需求

## 目标

把 VPNGate 志愿节点包装成类似商业动态住宅代理的服务：客户端只配置一个代理地址，通过用户名里的参数控制出口国家和出口 IP 的粘滞时长。引擎用内嵌的 OpenVPN 3 Core（选型依据见 [OPENVPN3_GO.md](OPENVPN3_GO.md)）。

## 接入格式

```
http://<账号>[-country-<国家>][-session-<会话ID>[-t-<分钟>]]:<密码>@<主机>:<端口>
socks5://<同上>
```

- 单账号：账号、密码来自配置文件，可用 `LOCAL_PROXY_USER` / `LOCAL_PROXY_PASS` 覆盖。
- `country`：ISO 3166-1 两位国家代码，大小写不敏感。
- `session`：字母、数字、下划线，1–64 个字符。
- `t`：粘滞分钟数，1–1440（最长 24 小时），默认 10；只能和 `session` 一起使用。
- 参数顺序不限，每个参数最多出现一次。

| 用户名 | 行为 |
| --- | --- |
| `user` | 轮换：每个新的代理连接换一个出口 IP |
| `user-session-abc` | 粘滞 10 分钟 |
| `user-session-abc-t-60` | 粘滞 60 分钟，到期后换出口 IP |
| `user-country-jp` | 只用日本节点，轮换 |
| `user-country-jp-session-abc-t-10` | 只用日本节点，粘滞 10 分钟 |

## 行为规则

1. 出口 IP 以隧道建好后实测的公网 IP 为准（通过隧道请求 `api.ipify.org`，失败再试 `icanhazip.com`）。不同节点可能共用一个 NAT 出口：实测筑波大学的学术节点 `219.100.37.x` 有几十个，但只共用十来个出口。所以"换 IP"指换到实测出口不同的隧道；对同一节点新建隧道，或换到同一 NAT 后的另一个节点，都不算换 IP。
2. 隧道连上但实测出口失败（握手成功却不转发流量），视为节点失败：立即关闭隧道，节点进入冷却。用了一段时间后静默失效的隧道（Core 没有报错，但不再转发流量；2026-11-13 部署时实测出现）同样处理：经过它的 DNS 或连接超时就立即体检，失败则下线，并在还没回应客户端之前把这次请求换到另一条隧道重试一次。
3. 粘滞期内，同一会话 ID 的所有新连接都走同一条隧道。节点断线时，下一个新连接改用其他出口（提前换 IP）。
4. TTL 到期后，同一会话 ID 的下一个新连接分到另一个出口 IP。符合条件的出口只剩原来那一个时，继续使用它并记录日志。
5. 隧道没有会话、也没有打开的连接时立即关闭（轮换请求的隧道在连接结束时关闭，会话隧道在 TTL 到期且连接全部结束时关闭）。
6. 已经建立的连接（例如长时间的 CONNECT 隧道）不受 TTL 影响，直到客户端关闭。
7. 同一会话 ID 在有效期内不能更换 `t` 或 `country`，否则拒绝。
8. 不同会话 ID 尽量分到不同出口 IP；出口数少于会话数时可以共用。
9. 认证失败返回 407（SOCKS5 认证失败）；认证通过但没有可用节点返回 503（SOCKS5 一般性失败）。
10. 默认监听 `127.0.0.1:7928`；镜像里由 `LOCAL_PROXY_HOST=0.0.0.0` 覆盖。

## 隧道按需连接

不预热：没有请求时不保持隧道，请求来了才连节点。连一个 VPNGate 节点要 2–8 秒，遇到失败的节点会换下一个重试（每个最长 15 秒，最多 5 个），这段等待用户可以接受（2026-11-13 确认）。

- **轮换请求**（不带 session）：每个代理连接都新连一个节点，连接结束就关闭这条隧道。挑节点时优先选出口 IP 最久没用过（或还没测过出口）的节点，让相邻请求换到不同 IP。
- **会话请求**：第一次请求时新连一条隧道，出口不能和其他会话正在用的 IP 重复；`t` 分钟内复用这条隧道；到期后，下一个请求新连一条出口不同的隧道。旧隧道上的连接全部结束后立即关闭。
- **同一节点同时只开一条隧道**：VPNGate 节点常拒绝同一客户端的并发登录（实测 `AUTH_FAILED`），正在使用中的节点不会再被选中。
- **并发上限**：同时存在的隧道不超过 `max_tunnels`；达到上限时，新请求共用一条现有隧道（同国家，会话优先共用没有其他会话的出口）；连可共用的都没有时等待，超时返回 503。
- **国家参数**：只在该国节点里挑。

## 节点来源

- 每 20 分钟拉一次 VPNGate API（`api/iphone`，每次约 100 台；官网页面显示总数约 5000 台，以后可考虑解析完整列表），失败时每分钟重试。
- 节点按 IP 去重并累计保存：每次列表只包含当时在线的一批，积累下来才能有更多出口 IP。
- **评分**：用 API 自带的 `Score`，只用于排序，不排除任何节点。VPNGate 官方只说明它"由质量参数自动计算"，没有公开公式；学术节点带宽大、在线稳定，通常排在最前。
- **用量记忆**：节点表记住每个节点上一次实测的出口 IP，以及每个出口 IP、每个 /24 网段最近一次被使用的时间，随节点表保存。挑中一个节点就记它的网段已用（不等连接结果），所以并发请求、连接失败后的重试都会换到别的网段；连上和关闭时再记出口 IP 及其网段。
- **选节点顺序**：先排除不能用的（国家不符、冷却中、已有隧道、已知出口正被其他隧道使用、会话到期时原来的节点和出口）；其余的依次按：网段最久没用过；同网段内出口 IP 最久没用过（没测过出口的视为没用过）；在最新列表里的按评分；不在列表里的按最近连成功的时间。没测过出口的节点按自身 IP 估计网段：志愿节点的出口大多就是节点 IP，学术节点的出口与节点 IP 同在 `219.100.37.0/24`。
- **为什么按 /24**：网站和黑名单常把一个 /24 当作同一来源；NAT 出口也通常在同一 /24 里。按 ASN（运营商）分组需要额外的 IP 库，而且日本家宽集中在少数几家运营商，粒度太粗；按单个 IP 分组则区分不了同一 NAT 后的节点。（2026-11-13 与用户确认按网段轮换。）
- **学术节点**：照常使用。"Academic Use Only"是运营者的使用声明，技术上并不限制连接；它们几十台共用一个 /24，按网段轮换时只算一组。
- 连接失败（包括实测出口失败）的节点冷却 10 分钟；连续失败 5 次，或 7 天没出现在列表里，就被淘汰（两个阈值可配置）。

## 实现状态

已实现：接入格式与参数解析、按需连接与即时关闭、按实测出口 IP 分配和避让、按 /24 网段和出口 IP 最久未用轮换、TTL 换 IP、隧道健康检查（连接时探测出口；请求超时时复查并换隧道重试一次；会话隧道空闲每 60 秒探测；Core 断线重连即下线）、节点累计与冷却淘汰、Docker 镜像（amd64 + arm64）。
