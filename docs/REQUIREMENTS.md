# 需求

## 目标

把 VPNGate 志愿节点包装成类似商业动态住宅代理的服务：客户端只配置一个代理地址，通过用户名里的参数控制出口国家和出口 IP 的粘滞时长。

## 接入格式

```
http://<账号>[-country-<国家>][-session-<会话ID>[-t-<分钟>]]:<密码>@<主机>:<端口>
socks5://<同上>
```

- 单账号：账号、密码来自配置文件，可用 `LOCAL_PROXY_USER` / `LOCAL_PROXY_PASS` 覆盖。
- `country`：ISO 3166-1 两位国家代码，大小写不敏感。
- `session`：字母、数字、下划线，1–64 个字符。
- `t`：粘滞分钟数，1–1440，默认 30；只能和 `session` 一起使用。
- 参数顺序不限，每个参数最多出现一次。

| 用户名 | 行为 |
| --- | --- |
| `user` | 轮换：每个新的代理连接分配一个出口 |
| `user-session-abc` | 粘滞 30 分钟 |
| `user-session-abc-t-10` | 粘滞 10 分钟，到期后换出口 IP |
| `user-country-jp` | 只用日本节点，轮换 |
| `user-country-jp-session-abc-t-10` | 只用日本节点，粘滞 10 分钟 |

## 行为规则

1. 出口 IP 就是 VPNGate 节点的 IP。"换 IP"指换到另一个节点；对同一节点新建隧道不算换 IP。
2. 粘滞期内，同一会话 ID 的所有新连接都走同一个节点。节点断线时，下一个新连接改用其他节点（提前换 IP）。
3. TTL 到期后，同一会话 ID 的下一个新连接分到另一个节点。符合条件的节点只剩原来那一个时，继续使用它并记录日志。
4. 已经建立的连接（例如长时间的 CONNECT 隧道）不受 TTL 影响，直到客户端关闭。
5. 同一会话 ID 在有效期内不能更换 `t` 或 `country`，否则拒绝。
6. 不同会话 ID 尽量分到不同节点；节点数少于会话数时可以共用节点。
7. 认证失败返回 407（SOCKS5 认证失败）；认证通过但没有可用节点返回 503（SOCKS5 一般性失败）。
8. 默认监听 `127.0.0.1:7928`；对外提供服务时设置 `LOCAL_PROXY_HOST=0.0.0.0`。

## 节点来源

- 每 20 分钟拉一次 VPNGate API，失败时每分钟重试。
- 节点按 IP 去重并累计保存：VPNGate 每次只列出当时在线的一批，攒下来才有更多出口 IP。
- 选节点时优先用最新列表里的（按 VPNGate 评分），其次是历史上近期连成功过的。
- 连接失败的节点冷却 10 分钟；连续失败 5 次，或 7 天没出现在列表里，就被淘汰（两个阈值可配置）。

## 暂不做

- 多账号、流量统计与计费、IP 白名单
- 管理界面
- IPv6 目标地址
- 按城市、ASN 筛选

## 引擎选型

隧道引擎目前是嵌入的 OpenVPN 3 Core（C++）。另设 benchmark，在受控环境中与直接调用 `openvpn` CLI 对比并发建连时间、内存、进程/线程数和停止耗时，用结果决定是否继续使用 Core。
